# PowerPlay

**PowerPlay** is an unofficial, lightweight **Plex-focused client for Amazon Fire TV**, derived from [Plezy](https://github.com/edde746/plezy) and distributed under **GPL-3.0**. It is tuned for movies and TV shows, ExoPlayer/Media3 playback, and Home Assistant control.

PowerPlay is not associated with or endorsed by Plex, Plezy, or Amazon.

## PowerPlay features

- **Plex-only movies and TV**: disables Jellyfin integration, music restoration, cloud Discover/requests, third-party trackers, Discord presence, Watch Together, and the Plezy companion remote.
- **ExoPlayer/Media3 video** with FFmpeg codec libraries; removes the MPV player runtime.
- **Fire TV optimizations**: improved navigation, startup behavior, artwork priority, Plex request handling, and memory budgeting.
- **Home Assistant deep links** for direct launch and continuous shuffled TV-show playback.
- **Independent application**: can be installed alongside the original Plezy, with separate sign-in and application data.
- **Purple PowerPlay branding**: launcher icons, alternate icons, TV banner, and splash art.

## Home Assistant and Android deep links

The Android package ID is `com.power.powerplay`, and the URI scheme is **`powerplay://`**, not `plezy://`.

Example Home Assistant / Android intent links:

```text
powerplay://shuffle?server=SERVER_ID&show=SHOW_RATING_KEY
powerplay://play?server=SERVER_ID&id=SHOW_RATING_KEY&mode=shuffle
```

For an ADB-connected Fire TV:

```sh
adb install -r PowerPlay-v1.0.0.apk
adb shell am start -a android.intent.action.VIEW -d 'powerplay://shuffle?server=SERVER_ID&show=SHOW_RATING_KEY' com.power.powerplay
```

The original Plezy package `com.edde746.plezy` and `plezy://` links remain independent; existing Plezy installations do not have to be removed.

This release is based on **Plezy 2.25.0** with the tested Fire TV optimization stack from [candidate run 41155352066](https://github.com/The-Power-0/PowerPlay/actions/runs/41155352066), rebranded and compiled in [PowerPlay candidate run 41249470717](https://github.com/The-Power-0/PowerPlay/actions/runs/41249470717), then promoted without recompilation.

**For the exact source corresponding to the published APK, use the `-Source.tar.gz` attachment above** plus the pinned native-source inputs and build instructions in that archive. GitHub's autogenerated "Source code" downloads, or the legacy repository root, are *not* substitutes for those release attachments. The maintained branch is being transitioned from a Plezy fork to a dedicated PowerPlay project; future source branches may differ.

The release candidate workflow lives in [`.github/workflows/powerplay-release-candidate.yml`](.github/workflows/powerplay-release-candidate.yml), with the [rebranding script](.github/powerplay/apply_rebrand.py) and manually approved [publication workflow](.github/workflows/powerplay-publish.yml). Upstream version updates are **not** automatically incorporated; future changes are selectively evaluated.

## Version and release policy

- Each individual feature release increments the patch version by **0.0.1** (for example, 1.1.0 → 1.1.1).
- A complete batch of features increments the minor version by **0.1.0** and resets the patch to zero (for example, 1.0.0 → **1.1.0**).
- Every stable PowerPlay publication is explicitly marked **Latest**. Candidate builds remain unpublished artifacts.
- `.github/powerplay/release.json` records the next version, a monotonically increasing Android build number, and SHA-256 pins for the published baseline source.
- The candidate workflow restores the exact published PowerPlay 1.0.0 source, applies the reviewed `.github/powerplay/next-version.patch`, and runs settings/default, import/export, and deep-link regression tests before compiling. It does not build from the legacy source at the repository root.
- The publication workflow promotes that signed candidate without rebuilding and verifies GitHub's Latest pointer afterward.
