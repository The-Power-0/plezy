Stage 11 — Plex network consolidation. Concurrent `fetchServerPrefs()` calls on the same PlexClient now share one in-flight future. Once the fetch completes (success or failure), the future is released so later lifecycle refreshes still contact Plex. The existing `/\:/prefs` endpoint, watched-threshold persistence and client failover are untouched. This narrowly scoped change does not deduplicate arbitrary requests or cache different Plex identities. Source-only validation; concurrency regression tests, Flutter compilation, network trace and device measurements are required before merge.
